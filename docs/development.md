# Локальная разработка

## Требования

- Node 24 (`.nvmrc`), pnpm 12 (`corepack enable pnpm`)
- Docker

## Первый запуск

```bash
cp .env.example .env
pnpm install
pnpm db:up
pnpm build:shared
```

## Порты

| Сервис       | Порт |
| ------------ | ---- |
| app (Nuxt)   | 4100 |
| api (NestJS) | 4200 |
| admin (Nuxt) | 4300 |
| MySQL        | 3307 |

Базы: `dodep` — разработка, `dodep_test` — e2e-тесты API.

## Команды

| Команда                             | Что делает                 |
| ----------------------------------- | -------------------------- |
| `pnpm db:up` / `pnpm db:down`       | поднять / остановить MySQL |
| `pnpm build:shared`                 | собрать `@dodep/shared`    |
| `pnpm lint`                         | ESLint во всех пакетах     |
| `pnpm format` / `pnpm format:check` | Prettier                   |
| `pnpm typecheck`                    | TypeScript во всех пакетах |
| `pnpm test`                         | unit-тесты во всех пакетах |

## API

```bash
cp api/.env.example api/.env
pnpm db:up
pnpm --filter @dodep/api db:migrate
pnpm dev
```

- API: http://localhost:4200/api
- Swagger: http://localhost:4200/api/docs
- WebSocket: ws://localhost:4200/api/ws

Проверено: прокси Nitro devProxy (`ws: true`) не проксирует `/api/ws` в дев-режиме — хендшейк падает с `404`. Обходной путь: `app/.env` с `NUXT_PUBLIC_WS_URL=ws://localhost:4200/api/ws` (подхватывается `useFeed` напрямую, без прокси), перезапустить `pnpm dev`.

Миграции: изменить `api/src/db/schema.ts` → `pnpm --filter @dodep/api db:generate --name <имя>` → `db:migrate`.

e2e-тесты пересоздают базу `dodep_test` при каждом запуске: `pnpm test:e2e` (MySQL должна быть поднята).

## Админка

Админка — отдельное приложение на http://localhost:4300 (в проде — `admin.dodep.fun`). Вход только по одноразовой ссылке с публичного сайта.

1. В `api/.env` должно быть `ADMIN_URL=http://localhost:4300`.
2. Зарегистрируйтесь на http://localhost:4100.
3. Выдайте себе права: `pnpm --filter @dodep/api admin:grant <ник>` (снять: `… admin:grant <ник> --revoke`).
4. Обновите страницу сайта — в шапке появится «Админка». Ссылка действует 60 секунд и только один раз.

Админская сессия — cookie `admin_sid` на `Path=/api/admin`, 12 часов. Публичная сессия к админскому API не подходит.

- Swagger админки: http://localhost:4300/api/admin/docs (только после входа)
- Публичный Swagger: http://localhost:4200/api/docs

Локально app и admin на одном хосте `localhost`, а cookie не различают порты: `sid` уходит и в admin, но админский API её игнорирует. В проде поддомены разные, cookie host-only.

В проде права выдаются так же, внутри контейнера API: `node dist/cli/admin-grant.js <ник>`.

## Фронтенд

- `ui/` — Nuxt layer: токены (`ui/app/assets/css/tokens.css`), базовые стили, компоненты `Ui*`, `useApi`, `useToast`, форматирование. Подключается через `extends: ['../ui']`.
- `app/` — публичный сайт на Nuxt 4 (srcDir `app/app/`), порт 4100.

```bash
pnpm dev          # shared (watch) + api:4200 + app:4100
```

В dev Nuxt проксирует `/api` и WebSocket `/api/ws` на `localhost:4200`. Если WebSocket не проходит через прокси, задать `NUXT_PUBLIC_WS_URL=ws://localhost:4200/api/ws` в `app/.env`.

| Переменная              | Назначение                                                        |
| ----------------------- | ----------------------------------------------------------------- |
| `NUXT_API_INTERNAL_URL` | адрес API для SSR-запросов (по умолчанию `http://localhost:4200`) |
| `NUXT_PUBLIC_WS_URL`    | явный адрес WebSocket (по умолчанию — тот же хост, `/api/ws`)     |

Правила кода фронтенда: компоненты — по папкам (`layout`, `auth`, `game`, `feed`, …), не больше ~300 строк; стили — `<style scoped>` на токенах; тесты — в `__tests__` рядом с кодом; состояние — `useState`, без Pinia. Stylelint проверяет `.css` и `<style>` в `.vue` (`pnpm lint`).

## Найденные баги прототипа

Список дополняется при переносе `prototype/v3`.

- Исход клика не объявлялся экранному диктору — добавлен `aria-live` в игровой консоли.
- Ползунки навигации и сегментов считались до загрузки шрифтов и только по глобальному `resize` — теперь `useResizeObserver` + `document.fonts.ready`.
- Раунд терялся при перезагрузке — восстанавливается через `GET /api/rounds/active`.
- Хэш раскладки считался асинхронно в браузере и мог отсутствовать — теперь приходит с сервера при старте раунда.
- Время в журнале и ленте форматировалось в часовом поясе браузера — теперь по Москве, без расхождений SSR и клиента.

Страницы правил, рейтинга, журнала и профиля:

- Рейтинг: клик по строке делал полную перезагрузку (`location.href`) — теперь клиентская навигация, ник в строке — обычная ссылка, доступная с клавиатуры.
- Рейтинг: поиск отправлял запрос на каждую букву, а ответы могли прийти не по порядку — теперь задержка 250 мс и отбрасывание устаревших ответов.
- Рейтинг: на мобильном подиум шёл в порядке 2-1-3 из-за `order` — теперь 1-2-3.
- Рейтинг: точки AI-типажей были недоступны с клавиатуры и экранному диктору — теперь это ссылки с `aria-label`, подсказка видна и при фокусе.
- Рейтинг: фактический RTP и баланс считались по демо-данным со «ставками», выдуманными из хэша ника — теперь из `GET /api/stats`.
- Правила: строки таблицы выплат выбирались только мышью — добавлены Tab/Enter/Space.
- Журнал: точка подсказки спарклайна считалась по захардкоженным 10/180 и съезжала при другой высоте; id градиента был общий для всех графиков — теперь координаты берутся из той же геометрии, что и линия, id уникальный.
- Журнал: ячейки клеток/ставки на мобильном скрывались по позиционному `nth-child`, задевая не те колонки — теперь скрываются ставка, клетки и выплата явно.
- Профиль: превью статуса показывало ссылки, которые сервер потом вырезал — теперь превью нормализуется той же функцией, что и сервер (`normalizeStatus` в `@dodep/shared`).
- Профиль: несуществующий игрок отдавал 200 — теперь SSR отвечает 404.
