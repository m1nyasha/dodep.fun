# Запуск AI-агентов

Один запуск создаёт **по одному участнику каждого профиля** из `agents/src/profiles/index.ts` и ведёт каждого до добровольной остановки, нехватки монет или лимита раундов. Сейчас в реестре один профиль — `loss-chaser`. Для десяти повторов используйте десять разных ключей запуска. Каждый ключ создаёт отдельный `experimentId`, новые аккаунты и независимые игровые исходы.

## Подготовка

1. Поднимите MySQL и примените миграции: `pnpm db:up`, затем `pnpm --filter @dodep/api db:migrate`.
2. В `api/.env` задайте `INTERNAL_AGENT_API_ENABLED=true` и случайный `INTERNAL_AGENT_API_TOKEN` длиной не меньше 32 символов. Запустите API.
3. На компьютере для записи скопируйте `agents/.env.example` в `agents/.env`, задайте `DEEPSEEK_API_KEY`, тот же `INTERNAL_AGENT_API_TOKEN` и `AGENT_API_URL=https://dodep.fun/api`. Ключ DeepSeek остаётся только в runner.
4. Проверьте `ruleVersion` и лимиты в `agents/runs/experiment.example.json`. Версия правил должна существовать и иметь стартовый баланс 10 000, минимум и шаг ставки по 100. Для короткого пилота можно создать отдельную конфигурацию с меньшим `maxRounds`.
5. Соберите runner: `pnpm --filter @dodep/agents build`.

Из каталога `agents/` запустите:

```bash
pnpm start --key pilot-001 --config runs/experiment.example.json
```

Повтор той же команды возобновляет тот же эксперимент. Новый ключ, например `pilot-002`, создаёт новую итерацию. Участники создаются один раз для каждой пары `experimentId + profileKey + slot`.

После `technical_stop` устраните причину и повторите команду с `--resume-technical`. Если у участника был открыт раунд, он продолжит его; закрыть запуск с незавершённым раундом API не позволит.

Runner поднимает локальный экран `http://127.0.0.1:4400`. На нём видны балансы, прогресс, текущее открытое поле и причины решений. Экран читает журнал из API и остаётся доступным после завершения до остановки процесса. Сырой локальный журнал вызовов модели пишется в `agents/runs/<key>.jsonl` и не попадает в Git.

Чтобы открыть экран позже без запуска модели, выполните из `agents/` `pnpm monitor --id <experimentId>`. ID печатается в начале запуска. Для этого достаточно API-токена; ключ DeepSeek не нужен.

Для экспорта применённых решений используйте внутренний API `GET /api/internal/experiments/<experimentId>/decisions` с Bearer-токеном. Ответ включает модель, расход токенов, действие, причину и результат. Манифест запуска доступен в `GET /api/internal/experiments/<experimentId>/monitor`.

## Как добавить характер

Добавьте файл инструкции в `agents/src/profiles/` и запись с уникальным `key`, названием и именем файла в `agents/src/profiles/index.ts`. Следующий запуск с новым ключом автоматически включит новый профиль. Количество экземпляров профиля в одной итерации остаётся равным одному.

## Важные границы

- Runner общается только с внутренним игровым API; модель видит баланс, правила, доступные действия, активный раунд и пять последних завершённых раундов. Мины текущего раунда не передаются.
- Условия, хеши промптов и lockfile, кодовый коммит и параметры модели сохраняются в манифесте. Его нельзя менять после создания запуска с тем же ключом.
- Сервер повторно проверяет каждое действие. `decisionId` делает повтор игрового запроса безопасным: запись решения, изменение баланса и раунда проходят одной транзакцией.
- Лимиты времени, числа вызовов модели и токенов помечают участника как `technical_stop`. Это не считается добровольным решением персонажа.
- Runner на твоём компьютере обращается к `/api/internal` через публичный HTTPS-маршрут. Этот маршрут закрыт отдельным Bearer-токеном длиной от 32 символов, отключён по умолчанию и отсутствует в публичном Swagger. Не используйте HTTP или слабый токен для удалённого API. Локальный экран слушает только `127.0.0.1`.
- Настоящий запуск требует действующего ключа DeepSeek и расходует токены; подготовка и тесты его не вызывают.
